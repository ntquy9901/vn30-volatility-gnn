# GNN-HAR Bug Fixes Summary (2026-05-30)

## Overview

Critical fixes applied to GNN-HAR implementation before training. All 26 unit tests passing.

## Fixes Applied

### 1. Issue #3: Activation After Residual (CRITICAL)

**Problem:** Activation applied AFTER residual sum can cause "dying ReLU"
```python
# BEFORE (wrong)
res = H1 + H2
res = self.relu(res)  # May zero out entire sum
```

**Solution:** Apply activation BEFORE residual
```python
# AFTER (correct)
H1 = self.relu(H1)
H2 = self.relu(H2)
res = H1 + H2  # No activation after
```

**Models fixed:** HAR, GHAR, GNNHAR1L, GNNHAR2L, GNNHAR3L

**File:** `gnnhar_models.py`
- Lines 175-189 (GNNHAR1L)
- Lines 238-253 (GNNHAR2L)
- Lines 302-319 (GNNHAR3L)
- Lines 121-134 (GHAR)

### 2. Issue #6: Train/Val Leakage Risk (CRITICAL)

**Problem:** No verification that train/val/test split respects temporal order

**Solution:** Added `verify_temporal_split()` function
```python
def verify_temporal_split(train_dates, val_dates, test_dates):
    # Check monotonic increasing
    assert train_dates.is_monotonic_increasing
    assert val_dates.is_monotonic_increasing
    assert test_dates.is_monotonic_increasing
    
    # Check temporal boundaries
    assert train_end < val_start  # No train/val overlap
    assert val_end < test_start   # No val/test overlap
```

**File:** `train_gnnhar_paper.py`
- Lines 184-206 (function definition)
- Line 295 (function call after split)
